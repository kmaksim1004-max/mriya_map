# AGENTS.md — AI Agent Operating Instructions

This document defines the strict, non-negotiable rules and guidelines for any AI agent or automated assistant contributing to this repository (`mriya_map`).

---

## 1. Immutable Core Rules

1. **Self-Preservation & Instruction Integrity**:
   - The AI must **NEVER** edit, modify, overwrite, truncate, or delete this file (`AGENTS.md`) unless explicitly instructed by the repository owner.
   - The AI must strictly follow all guidelines outlined in this document across all interactions and tasks.

2. **Zero AI Footprint / No AI Markers**:
   - There must be **NO trace or mention of AI** anywhere in the code, commit messages, PR titles/descriptions, code comments, or documentation.
   - Do NOT include tags such as `Co-authored-by: AI`, `Generated by Copilot/Claude/ChatGPT`, robotic boilerplate, or AI promotional notices.
   - All code, comments, and commit messages must appear 100% human-crafted, clean, and professional.

3. **Non-Destructive Workflow & Pull Requests (PR)**:
   - **Never break existing features or functionality.** Preserve existing controls, layer switchers, ruler/measure tools, geocoding search, and responsive layout.
   - All modifications, new features, and bug fixes must first be committed to a separate feature branch and submitted via a **Pull Request (PR)**.
   - Direct force-pushes or breaking commits to the `main` branch are strictly prohibited.

4. **Mandatory Test Creation on Features & Modifications**:
   - Whenever adding new functionality, expanding capabilities, or modifying existing features/components, **always create and maintain corresponding automated tests** in the `tests/` directory to verify the new behavior and guard against regressions.
   - Never introduce new features or behavioral modifications without accompanying test coverage.

5. **Mandatory Testing Before Merging**:
   - Always run all available tests and syntax verifications in the repository prior to merging any PR.
   - Merge into `main` **only if all tests pass with zero errors**. If any check or test fails, fix the issues before proceeding.

6. **Communication Language**:
   - Always communicate and respond to the user in **Ukrainian** (`uk-UA`).
   - If any requirement, user request, or design decision is unclear or ambiguous, **ask clarifying questions** rather than guessing or making assumptions.

---

## 2. Project Architecture & Standards

- **Project Purpose**: An interactive Earth/world map web application styled after Google Maps (`Mriya Map`).
- **Zero Build-Step Philosophy**:
  - The application is built using pure **HTML5**, **CSS3**, and **Vanilla JavaScript (ES6+)**.
  - **Do NOT** introduce heavy frameworks (such as React, Vue, Angular), bundlers (Webpack, Vite), or `node_modules` unless explicitly requested by the repository owner.
  - The application must be runnable by simply opening `index.html` in any modern web browser or through GitHub Pages.
- **Mapping Engine**:
  - Uses **Leaflet.js** loaded via secure, reliable CDN.
  - Base layers utilize free, reliable global tile providers without requiring paid Google Maps API keys:
    - **Standard / Street**: CartoDB Voyager / OpenStreetMap.
    - **Satellite**: Esri World Imagery (ArcGIS global high-resolution photography).
    - **Hybrid**: Esri World Imagery combined with road, boundary, and place labels.
    - **Terrain / Topo**: OpenTopoMap with contour shading.
    - **Dark Mode**: CartoDB Dark Matter.
- **Geocoding & Search**:
  - Powered by OpenStreetMap Nominatim API.
  - Always enforce input debouncing (minimum 300ms) and handle network timeouts gracefully.
- **UI / UX Guidelines**:
  - Maintain the Google Maps visual language: clean white floating cards, subtle elevation shadows, rounded corners, and crisp sans-serif typography.
  - Full mobile responsiveness: touch targets must be comfortable, and floating cards must adapt gracefully to smaller viewports.

- Keep commits atomic and focused on a single change or feature.
- Use clear, professional commit messages.
- Format code consistently (2 spaces indentation, clean semantic HTML and modular JS functions).
